Slide the clock to see predicted congestion change

Important limit: Google's live traffic layer only ever shows the current moment — there is no API to rewind it to yesterday or fast-forward it to tomorrow, for any price. So this slider does not scrub real live traffic. It drives our own predicted intensity model instead: each landmark's calendar-risk severity for the day selected above, shaped by a realistic hour-of-day pattern for its type (prayer times for a masjid, morning/evening darshan hours for a temple, Sunday morning mass for a church) plus an ambient citywide commute floor. The real live traffic layer only switches on below when the slider actually matches the current real hour.

Add a location not in this list

Drop a pin on the Map tab (or type coordinates directly) to add your own location — it's computed with the same weekly/festival rules as the built-in 33 and joins every view (ranking, maps, zone timelines) immediately. Stored only in this browser's local storage — not shared with anyone else, not synced anywhere, gone if you clear browser data. Note: it won't get the built-in landmarks' proximity-conflict escalation (see Recommendations tab) since that's computed once, server-side, against the full landmark set.

What this report actually is: a triage list built from five illustrative, sample-data variables — religious calendar (weekly peak day + festival dates), school drop-off/pickup timing, IT campus/tech-corridor shift-change timing, heavy-vehicle entry-corridor timing, and parking/market saturation — plus one added signal: a proximity-conflict check that escalates a zone's severity one tier when a geographically close landmark of a known-conflicting kind (e.g. a school within 1.2km of a truck corridor) is also active on the same day. None of this is measured traffic-volume data; it prioritizes where a real study or intervention is worth spending effort, not a replacement for one. Coordinates and timing windows are illustrative — verify locally before acting on any single row.

    What this tab actually is: a triage aid, not a validated engineering result. There's no real road-junction geometry or turning-movement count behind this — the "after" map scales a reduction (20% at High, 30% at Extreme predicted severity) and a suggested median-opening offset (150–200m / 200–300m) off our own predicted-severity rank, since that's the only signal available here; both ranges come from the published U-turn/median-relocation studies cited in docs/RESEARCH.md, which also report bigger benefits where baseline congestion is worse — which is the actual scientific basis for tiering by severity at all. Recommended next step for any ticked location: commission a real turning-movement/volume count at that junction (an ITE-style warrant study) before changing anything — this tool's job is to prioritize where that study's time goes, not to replace it.
