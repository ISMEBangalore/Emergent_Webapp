Bengaluru Traffic Lab · sample output

What the analysis toolkit actually produces

Two views generated by the CLI added to bengaluru-traffic-lab/: which roads matter most to the network, and which weekly/festival days push congestion up near a tagged religious site. Both are computed straight from the sample data shipped in the repo — nothing here is hand-drawn.

Generated by traffic_lab.report critical-roads and traffic_lab.report festival-risk against data/sample_network.csv and data/landmarks.sample.csv + data/festivals.sample.yaml. Both source files are marked illustrative in the repo — see docs/RESEARCH.md before using this on a real road network.

variable #3 · critical roads

Which road, if closed, hurts the network most

Edge color/thickness is betweenness centrality — how much through-traffic a segment carries between everything else. The bridge between the two clusters scores 16× higher than the weakest link and, uniquely, splits the network in two if it closes.

variable #4 · real coordinates

Where these landmarks actually sit

Marker positions are a true projection of each landmark's real lat/lon — not a stylized layout. The faint gray points (Cubbon Park, Vidhana Soudha, Majestic, KR Market, MG Road, Lalbagh) are well-known reference points for orientation only; they're not part of the dataset. Step through the day to watch risk shift.

Road geometry isn't drawn here: this sandbox's network egress blocks OpenStreetMap/Overpass/Nominatim outright, so there's no real street data available to plot alongside these points. graph_io.fetch_osm_graph() already supports pulling a real road network — run the same criticality analysis from a machine with normal internet access to get an actual street-level version of the map in the first section.
